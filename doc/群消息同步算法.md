# 群聊消息客户端同步算法完整解析


## 核心概念定义（先统一理解）
1. **反向加载**：从**最新消息**往**最早消息**加载（向上翻历史消息）
2. **正向加载**：从**旧消息**往**最新消息**加载（重连收新消息）
3. **标记规则**（客户端本地消息标记，仅用于同步逻辑）
   - `【`：**历史断点标记**，表示此条之前还有未加载的历史消息
   - `】`：**最新消息尾标记**，表示此条是当前最新消息
   - `*`：**初始消息标记**，表示此条是群聊最早的第一条消息，无更早数据
4. **分页标准**：固定每页加载 `100条` 消息
5. **关键接口**
   - `FindGChatMsgBackwardBetween`：按ID区间反向拉取消息（节省流量）
   - 无ID区间反向拉取：纯反向加载最新消息

---

## 一、总览：三大触发场景
1. **登录/重连**：初始化消息数据、补全最新消息
2. **界面拖动加载**：向上滑动加载历史消息
3. **网络请求返回**：处理服务器返回数据，更新本地/内存

---

## 二、分场景完整流程
### 场景1：登录 / 重连后初始化
```
开始
  ├─ 加载本地数据库消息
  │
  ├─ 【分支1：本地无任何数据】
  │    └─ 执行【纯反向加载】（拉最新消息）
  │         └─ 走 3.7 反向加载返回逻辑
  │
  └─ 【分支2：本地已有数据】
       ├─ 给本地最后一条消息加标记 】
       ├─ 取本地第一条消息ID = littleId（加载截止点）
       ├─ 调用 FindGChatMsgBackwardBetween(littleId) 反向区间拉取
       └─ 处理返回结果（核心校验）
            ├─ 1. 新数据覆盖了本地旧数据 → 正常更新，移除末尾标记 】
            ├─ 2. 新数据未覆盖，出现空隙
            │    ├─ 若返回=100条：未加载完，第一条加【，丢弃旧数据
            │    └─ 若返回<100条：理论异常，不处理
            └─ 3. 返回空数据：无新消息，修改标记为 】
```

---

### 场景2：界面拖动（向上翻历史消息）
```
开始
  ├─ 1. 检查第一条消息：若标记为 * → 已到最早消息，停止加载
  ├─ 2. 执行【内存检查断点并加载远程（3.2）】
  │    └─ 返回false → 停止；返回true → 继续
  └─ 3. 执行【本地加载并检查（3.3）】
```

## 三、核心函数标准化流程（原文3.1~3.8）
### 3.1 拖动加载函数（入口）
1. 第一条消息标记`*` → 终止加载
2. 调用**3.2 内存检查**
   - 返回`true`：继续执行
   - 返回`false`：终止加载
3. 无标记/需要本地加载 → 调用**3.3 本地加载**

### 3.2 内存检查断点并加载远程（核心判断）
**返回值：true=需要继续加载；false=终止加载**
1. 第一条消息标记`*` → 返回`false`
2. 消息**无【标记** → 返回`true`
3. 第一条消息有`【`标记
   - 以此消息ID为`littleId`
   - 调用`反向between`拉取历史
   - 返回`false`

### 3.3 本地加载并检查
1. 从指定ID**反向查询本地数据库**
   - 本地无数据 → 调用**网络反向加载**
2. 本地有数据
   - 检查数据中是否有`【`标记
     - 有：截断标记前数据，以最后一条为`littleId` → 反向between加载
     - 无：直接以最后一条为`littleId` → 反向between加载

### 3.4 初始化加载
直接执行：**3.3 本地加载并检查**

### 3.5 重连加载
1. 本地无数据 → 执行**3.4 初始化加载**
2. 本地有数据 → 执行**正向加载**

### 3.6 正向加载返回（仅重连场景）
1. 无任何标记处理
2. 数据直接入库 + 加入内存
3. 若返回数据**少于100条** → 继续加载

### 3.7 反向加载返回（仅本地无数据时）
内存为空时触发：
1. 返回**=100条**：第一条加`【` → 入库
2. 返回**<100条**：第一条加`*`（最早消息）→ 入库

### 3.8 反向between加载返回（最常用，带ID区间）
参数：`littleId、bigId`，支持`littleId=0`
1. 返回**=100条**
   - 第一条加`【` → 入库
   - 若内存前有数据（重连）→ 继续加载，直到覆盖前一条
2. 返回**<100条**
   - 已覆盖前边数据 → 移除边界标记 → 入库
3. 返回**=1条**
   - 已到群聊初始消息 → 标记为`*` → 入库

## 四、标记规则速查表（开发必备）
| 标记 | 含义 | 触发场景 |
|------|------|----------|
| `*` | 群聊**最早第一条消息**，无更早数据 | 反向加载返回<100条 / 返回1条 |
| `【` | 历史断点，此条之前还有未加载消息 | 反向拉取满100条 / 长时间未登录 |
| `】` | 当前最新消息尾标记 | 重连有本地数据时初始化 |

---

## 五、关键业务规则总结
1. **流量优化**：优先使用`反向between`区间拉取，避免全量拉取
2. **数据连续性**：加载必须覆盖本地旧数据，出现空隙则丢弃旧数据，保留新数据
3. **边界判断**：
   - 满100条=未加载完，加断点`【`
   - 不足100条=已加载到头，加初始标记`*`
4. **重连特殊逻辑**：短时间重连用**正向加载**收新消息，不处理标记
5. **异常兜底**：不足100条还未覆盖旧数据 → 理论异常，不做处理
